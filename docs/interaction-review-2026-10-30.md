# 交互故障回归记录 · 2026-10-30

## 已复现的问题

在旧生产版本 `c2e29f0` 的 `/admin/studio` 修改字段后，点击侧栏链接，再选择“保存后离开”。当保存请求保持 pending 时，弹窗的关闭、放弃修改、继续编辑全部 disabled，Escape 无法关闭；Radix 同时设置 `body.style.pointerEvents = 'none'`，因此页面背景也不能操作。

验证时仅在浏览器拦截该 PUT 请求并延迟返回模拟 503，未向生产服务发送保存请求。最后选择放弃修改恢复页面。这个复现说明保存卡住可以造成整页无法点击；尚不能据此断言用户遇到的每一个按钮问题都是同一原因。

另一个独立问题是根布局默认预加载 Geist Sans/Mono 的全部 8 个静态字体文件。浏览器会对短时间内未使用的字重产生 preload 提醒。此提醒不等同于 JavaScript 运行错误，也不是已证明的按钮失效原因。

## 修复和回归重点

- 保存进行中仍可继续编辑、关闭确认框、按 Escape 或点击遮罩退出。已开始的保存继续完成，重复保存和放弃操作保持互斥。
- 每次离页确认有独立身份。取消后，旧保存结果不能消费新的离页意图。
- 保存回调也必须遵守这一身份约束：取消后的旧请求不能关闭正在编辑的表单、覆盖新输入或跳转。
- 创建请求成功后保留新记录的 ID/revision；继续编辑再保存应更新该记录，避免重复创建。
- 关闭这两组字体的主动 preload，保留 `font-display: swap` 和原字体配置。
